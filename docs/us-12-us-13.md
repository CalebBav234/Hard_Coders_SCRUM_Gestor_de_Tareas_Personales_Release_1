# US-12 y US-13: historial y búsqueda de tareas

## Alcance implementado

- **US-12 — Historial unificado:** la interfaz muestra tareas terminadas y eliminadas lógicamente. Cada tarjeta conserva su título, descripción, prioridad, categoría, tiempo activo y una línea temporal desplegable con los cambios de estado.
- **US-13 — Buscar tareas:** las listas de tareas actuales y de historial tienen búsquedas independientes por título o descripción.

La búsqueda se ejecuta en PostgreSQL, es parcial e ignora mayúsculas y acentos. Los caracteres `%`, `_` y `\` se tratan como texto literal para evitar coincidencias inesperadas. La consulta admite hasta 160 caracteres y usa parámetros enlazados; no concatena entradas del usuario en SQL.

## API

```http
GET /api/tasks?q=informe
GET /api/tasks/history?q=reunion
```

`q` es opcional. Si falta o contiene solo espacios, se devuelve la lista completa correspondiente.

El historial devuelve cada tarea archivada con un arreglo `events`, ordenado del cambio más reciente al más antiguo:

```json
{
  "id": 12,
  "title": "Preparar reunión",
  "status": "TERMINADA",
  "deletedAt": null,
  "events": [
    {
      "fromStatus": "ACTIVA",
      "toStatus": "TERMINADA",
      "changedAt": "2026-08-31T18:00:00Z"
    }
  ]
}
```

## Base de datos

El historial de la API consulta las tablas existentes desde V001 y las transiciones de V002. **Funciona tanto con V001/V002 como con V003 aplicada**: ya no depende de que exista `v_task_archive`. Se mantiene V003 como vista de consulta para pgAdmin y otros clientes SQL, sin cambiar una migración ya compartida.

Para mantener el esquema completo al día, ejecuta desde la raíz con la contraseña del propietario:

```powershell
.\database\scripts\migrate.ps1
.\database\scripts\verify-local.ps1
```

La migración `V003__task_archive.sql` crea `task_manager.v_task_archive`. Esta vista incluye tareas con estado `TERMINADA` o con `deleted_at` informado. En una tarea activa eliminada, el tiempo efectivo queda congelado en la fecha de eliminación.

## Uso en la interfaz

1. Usa los enlaces **Mis tareas** e **Historial de tareas** de la cabecera para ir directamente a cada sección.
2. En **Mis tareas**, escribe texto y pulsa **Buscar** para filtrar las tareas visibles.
3. En **Historial de tareas**, consulta las terminadas y eliminadas; usa su campo de búsqueda para recuperar contexto anterior.
4. Pulsa **Ver cambios de estado** para desplegar la línea temporal.
5. Pulsa **Limpiar** para volver a la lista completa.

Al completar, reabrir, editar o eliminar una tarea, la sección de historial se actualiza automáticamente. Los errores de red y las búsquedas sin coincidencias muestran mensajes controlados y comprensibles.

Las tareas activas o inactivas no eliminadas permanecen en **Mis tareas**, no en el archivo. Al reabrir una terminada sale del archivo mientras está activa; sus transiciones no se borran y vuelven a verse al terminarla de nuevo.

## Si el historial no aparece

- **No existe la sección:** comprueba que backend y frontend se ejecuten desde esta misma rama y reinicia ambos. Antes de fusionar el PR #5, `develop` no contiene esta interfaz.
- **El servidor devuelve 404:** el backend iniciado es anterior a US-12; la pantalla indica que debe actualizarse y reiniciarse.
- **No hay registros:** completa una tarea activa o elimina una tarea de prueba, y limpia el filtro del historial. Una búsqueda sin coincidencias no significa que se hayan perdido datos.
- **Error de conexión:** comprueba el backend, PostgreSQL y las variables `SPRING_DATASOURCE_*`. La pantalla muestra un error, no un mensaje engañoso de archivo vacío.
- **Base sin V003:** antes producía `relation task_manager.v_task_archive does not exist`. La consulta ahora usa las tablas existentes y sigue funcionando sin esa vista.

Para probar el PR antes de fusionarlo:

git pull --ff-only origin codex/feature/us-12-us-13

Reinicia Spring Boot y Angular desde este repositorio. Usa `http://localhost:4200` para el frontend (origen permitido por CORS). `docker compose up -d` no aplica nuevas migraciones sobre un contenedor ya inicializado; usa `migrate.ps1` con los datos de conexión correspondientes. No borres el volumen para actualizarlo.

## Regresión de la integración con develop

Se conserva el contador en vivo y `TimeFormatPipe` de US-15, además de las búsquedas y las notificaciones hacia el historial. Una recarga solicitada mientras hay otra pendiente cancela la respuesta antigua y consulta de nuevo, evitando perder la tarea recién terminada.

Pruebas ejecutadas: 36 de frontend; 44 unitarias y 2 de integración real del backend (46), estas últimas tanto sobre V001/V002 como sobre V001/V002/V003. Se comprobó en navegador la finalización, aparición automática, búsqueda por descripción y apertura de transiciones.

Las pruebas PostgreSQL son optativas y **deben ejecutarse exclusivamente sobre una base desechable**: crean registros de prueba y no los borran. Aplica primero V001/V002 con los roles del proyecto; repite después de aplicar V003 para cubrir ambos escenarios.

```powershell
# Terminal del backend; URL y contraseña exclusivas de la base de pruebas.
$env:HISTORY_TEST_DB_URL='jdbc:postgresql://localhost:55439/history_test?currentSchema=task_manager'
$env:HISTORY_TEST_DB_PASSWORD='CONTRASENA_DE_PRUEBA'
mvn test
Remove-Item Env:HISTORY_TEST_DB_URL, Env:HISTORY_TEST_DB_PASSWORD
```

Sin `HISTORY_TEST_DB_URL`, `mvn test` ejecuta las pruebas unitarias y omite las 2 de integración. El esquema real del equipo no se modifica automáticamente.
