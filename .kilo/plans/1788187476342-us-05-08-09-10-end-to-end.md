## 2. Exact Problem / Root Cause Found

**Root cause**: The original feature branch had `TaskRepository` depend on `v_task_archive` view (defined in V003 migration). Environments with only V001/V002 migrations would fail with "relation `task_manager.v_task_archive` does not exist".

**Fix applied**: `TaskRepository.java` now uses an inline `ARCHIVE_SOURCE` subquery that reads directly from `task_manager.tasks` and `task_manager.categories` tables. V003 remains as an optional convenience view for SQL clients but is no longer an API dependency.

## 6. Integration Sequence

1. Task state change in `TaskList` → emits `historyChanged`
2. `app.html` catches `historyChanged` → calls `taskHistory.loadHistory()`
3. `TaskHistory.loadHistory()` → `TaskService.listHistory()` → `GET /api/tasks/history`
4. Backend returns `TaskHistoryResponse[]` with embedded `events` array
5. Frontend renders history cards with timeline

Search flow:
1. User enters search term in history view
2. `searchHistory()` sets `activeSearch` and calls `loadHistory()`
3. `TaskService.listHistory(query)` → `GET /api/tasks/history?q=...`
4. Backend applies `SEARCH_PREDICATE` (accent-insensitive LIKE on title + description)
5. Results displayed with search summary or empty state
